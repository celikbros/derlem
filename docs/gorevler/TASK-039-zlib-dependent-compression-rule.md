## Goal

The same line gets the same `tr-web-v1/v2` verdict on every interpreter the project uses.

## Why

`extreme_repetition` (and the `repeated_segments` gate that shares the `compressed_enough`
precondition) uses `len(zlib.compress(raw, level=9)) * 100 <= len(raw) * 18`. Python 3.14 on
Windows ships **zlib-ng** (`zlib.ZLIB_RUNTIME_VERSION = 1.3.1.zlib-ng`); Python 3.13 ships
classic zlib 1.3.1. Their deflate output lengths differ by a few bytes, so lines sitting on the
18 % boundary flip. Measured 2026-09-20: v3 (produced with the root `.venv`, 3.14) kept 7 lines
that v4 (produced with `worker/.venv`, 3.13) rejected with `extreme_repetition`; one of them
(sha256 `09be9e00…`, 7,700 bytes, mojibake e-commerce page) is kept by the 3.14 CLI and dropped
by the 3.13 CLI on a one-line input: 7,699 raw bytes compress to 1,386 bytes under zlib-ng (18.002 %, above the 18 % threshold → kept) and to 1,384 bytes under zlib 1.3.1 (17.976 % → dropped). Two bytes. All 7 are double-encoded spam pages — the *verdict* is
right, the *reproducibility* is not: the rejection report and the manifest cannot be
regenerated byte-for-byte on another interpreter.

## Scope

- Record `zlib.ZLIB_RUNTIME_VERSION` and the interpreter version in the clean-candidate
  manifest (immediately; no behaviour change).
- Replace the zlib ratio with an implementation-independent measure, or pin the policy to a
  named implementation and refuse to run on another: options measured on the 100k slice
  (agreement with the current verdicts, runtime). Candidates: unique-5-gram ratio alone (already
  computed), a pure-Python LZ77-style estimate, or `zlib` with a fixed strategy + recorded
  version and a documented tolerance band (lines within ±1 % of the threshold reported as
  `borderline` rather than decided).
- New policy version (`tr-web-v3`) — v1/v2 verdicts are frozen history; existing tests keep
  asserting them under the interpreter that produced them (skip with reason elsewhere).
- Tests: the boundary line above as a fixture; the verdict must not depend on
  `ZLIB_RUNTIME_VERSION`.

## Out of scope

- Changing v3/v4 outputs (frozen artifacts; the 7 drops stay recorded).
- The audit pack (TASK-020) — its sheet was drawn from the v3 report, unaffected.

## Acceptance criteria

- [ ] Agreement with `tr-web-v2` on the slice reported (lines changed, by reason).
